\begin{abstract} 
We mechanize two operational semantics for \prologP with cut
and prove them equivalent, in the Rocq prover. The first semantics
closely models the \elpiP's implementation,
it is based on a stack of choice points and is well suited for studying
optimizations employed by \prologP abstract machines. 
The second semantics is instead based
on and-or trees, in which the branches pruned by the cut operator are
made explicit.

We use the tree-based semantics (1) to prove properties about the effect of
the cut operator in the evaluation of choice points, since the
rules from classical logic do not apply, and (2) to reason about the determinacy
analysis introduced in Elpi version~3.0, which statically identifies
computations that produce at most one result.%
\end{abstract}

\section{Introduction}


\elpiP is a dialect of \lprologP (see \cite{1991miller-pf,Miller_Nadathur_2012,dunchev15lpar,TASSI_2019})
used as an extension language for the \rocqP prover (formerly the \coqP proof
assistant). \elpiP has become an important infrastructure component: several
projects and libraries depend on it~\cite{krebbers25,Trakt,Trocq,Maas2024,fissore2023,fissore2024}.
Examples include the Hierarchy-Builder library-structuring tool~\cite{cohen_et_al:LIPIcs.FSCD.2020.34}
and Derive~\cite{tassi2018,tassi2019,tassi2023}, a program-and-proof synthesis
framework with industrial applications at SkyLabs AI.

Starting with version 3, \elpiP is equipped with a static analysis for
determinacy~\cite{10.1007/978-3-032-15981-6_5} to help users tame
backtracking. \rocqP users are familiar with functional programming but
not necessarily with logic programming, in particular uncontrolled backtracking
is a common source of inefficiency and makes debugging harder. The
determinacy checker identifies predicates that behave like functions,
i.e., predicates that commit to their first solution and leave no
\emph{choice points} (places where backtracking could resume).

This paper reports our first steps towards a mechanization, in the \rocqP
prover, of the determinacy analysis from~\cite{10.1007/978-3-032-15981-6_5}.
We focus on the control operator \emph{cut}, which is useful to restrict
backtracking but makes the semantics depart from a pure logical reading.

We formalize two operational semantics for \prologP with cut. The first is a\marginpar{sottolineare che checking = user da le signature}
stack-based semantics that closely models \elpiP's implementation and is
similar to the semantics mechanized by Pusch in \isabelleP~\cite{10.1007/BFb0105415}
and to the model of Debray and Mishra~\cite[Sec.~4.3]{10.1016/0743-1066(88)90007-6}.
This stack-based semantics is a good starting point to study further
optimizations used by standard \prologP abstract machines~\cite{warren1983abstract,10.7551/mitpress/7160.001.0001},
but it makes reasoning about the scope of cut difficult. To address
this limitation we introduce a tree-based semantics in which the branches
pruned by cut are explicit and we prove the two semantics equivalent.
Using the tree-based semantics, we then prove some properties about the
impact of evaluating the cut in disjunctive querys. For example, unlike in
classical logic, $q_1 \lor q_2$ is not equivalent to $q_2 \lor q_1$,
since $q_2$ may be cut-away by $q_1$.

Finally, we use the formal semantics to prove the correctness of a static
determinacy analysis~\cite{10.1007/978-3-032-15981-6_5}. Intuitively,
nondeterminism arises when a computation can be completed by applying two
different rules. We exclude this situation in two ways. First, we check for
overlapping rule heads: if two heads do not overlap in the inputs they
accept, then no query can unify with both. Second, we account for the
presence of cut in rule premises: once
a rule whose premises contain a cut succeeds, all remaining rules are discarded
and all choice points allocated by premises preceeding the cut are discarded.
We show that if every rule defining a predicate passes this analysis, then
any call to that predicate leaves no choice points.

Both semantics share the same notion of program, written $\mathbb{P}$.
\Cref{fig:progx} is our running example. A program consists of a list of
rules \coqIn{R} together with a signature environment \coqIn{sigT}. Besides
the arity of each predicate, a signature specifies which arguments are
inputs and which are outputs, and whether the predicate is deterministic.

A rule consists of a head term \coqIn{Tm} and a list of premises. Each
premise is an \coqIn{Atom}, i.e. either the cut operator or a predicate
call. Terms \coqIn{Tm} include predicate symbols, data, and variables. In
the concrete syntax, variables are written with capital letters, and
predicate application follows the $\lambda$-calculus style (no
parentheses).

The set of variables \coqIn{V} is countable. We represent substitutions
$\Sigma$ as finitely supported maps from variables to terms, using the
finmap library~\cite{finmap}.
The empty substitution is written $\epsilon$ while
the composition of two substitutions $\sigma_1$ and $\sigma_2$ with
disjoint supports as $\sigma_1 + \sigma_2$.

The backchaining operation applies all rules to a query term; it is
central to both semantics.

\subsection{The cut operator}
\label{sec:cut-op}

The cut operator in \textsc{\elpiP} implements the \emph{hard cut}
(see, e.g., the documentation of \textsc{SWI-Prolog}~\cite{xxx}).
Whenever the backchaining function \coqIn{bc} returns a list of alternatives,
the first one is explored immediately, while the others are suspended as
\emph{choice points}. Within a given alternative, premises are processed from
left to right. When a cut is encountered, it discards (i) all choice points
created by \coqIn{bc} for the current call and (ii) all choice points created
while executing the premises preceding the cut.

For example, consider the program $P$ in \cref{fig:progx} and the query
$\elpiIn{g 0 R}$.
Both rules for \eI{g} apply to this query. Backchaining therefore returns the
following two alternatives:\\
\[
  [(\sigma_1, [\eI{r A B, f B C, !}]),\; (\sigma_2, [\eI{f D E, f E F}])]
\]
with
$
  \sigma_1 \coloneq \{\eI{A} \mapsto \eI{0}, \eI{B} \mapsto \eI{C}\}
$
and
$
  \sigma_2 \coloneq \{\eI{D} \mapsto \eI{0}, \eI{F} \mapsto \eI{R}\}
$.
For simplicity, we choose an example where variable refreshing plays no role,
so we do not discuss the set \FV{} any further.

Execution continues with the first premise of the first alternative, namely
\eI{r A B} under $\sigma_1$, i.e. \eI{r 0 C}. The remaining alternatives are
stored as choice points.
Backchaining \eI{r 0 C} returns
$
  [(\sigma_3, []), (\sigma_4, []), (\sigma_5, [\eI{!}])]
$
where
$
  \sigma_3 \coloneq \sigma_1 + \{\eI{B} \mapsto \eI{0}\}
$
;
$
  \sigma_4 \coloneq \sigma_1 + \{\eI{B} \mapsto \eI{1}\}
$
and
$
  \sigma_5 \coloneq \sigma_1 + \{\eI{B} \mapsto \eI{2}\}
$.

Since all rules for \eI{r} have empty premises, we chose the first success,
save the others as choice points, and continue with \eI{f B C} under $\sigma_3$,
that is, \eI{f 0 C}.
This time, backchaining fails (no rule for \eI{f} matches input $0$). We
therefore backtrack to the most recently introduced choice point and retry
\eI{f B C} under $\sigma_4$, i.e. \eI{f 1 C}. This succeeds with
$\sigma_6 \coloneq \sigma_4 + \{\eI{R} \mapsto \eI{2}\}$.

We now reach the cut. At this point there are still two unexplored
alternatives: one from the third rule for \eI{r} and one from the second rule
for \eI{g} (respectively, $\sigma_5$ and $\sigma_2$). Both are discarded,
because they were created when, or after, the first rule for \eI{g} was
selected. (In contrast, a cut does not discard choice points created earlier;
in this example, there are none.)

The final solution is:
$
  \{\eI{A} \mapsto \eI{0}, \eI{B} \mapsto \eI{1}, \eI{C} \mapsto \eI{R},
  \eI{R} \mapsto \eI{2}\}
$.

In Sections~XX and~YY we provide fully mechanized operational semantics for
\prologP with cut. They differ in how they represent the ongoing computation,
in particular how alternatives are stored and how they are pruned by cut.

\section{And-Or Tree semantics}
\begin{figure}
    % \input{tex_code/tree_def.tex}
    \begin{coqcode}
Inductive tree ~$\coloneq$~
  | KO | OK                            (* failure and success *)
  | Todo of Atom                       (* unexplored branch *)
  | Or   of option tree & ~$\Sigma$~ & tree ~$\!$~    (* $A \lor B_\sigma$ *) 
  | And  of tree & list Atom & tree.   (* $A \land_{B_0} B$ *)
\end{coqcode}
    \caption{State of the tree-based semantics: And-Or tree}
    \label{fig:tree-ty}
\end{figure}

An And-Or tree is a stratified, variable-width tree. It consists of two kinds
of layers that alternate: a disjunctive layer is followed by a conjunctive
layer and vice versa. At the root (a query), the tree records a list of
alternatives (an Or-layer); for each alternative, it records a list of
subqueries to be solved (an And-layer). Intuitively, solving a query requires
solving one alternative in the Or-layer, but all subqueries in the
corresponding And-layer.

The tree is built incrementally. It therefore contains a \coqIn{Todo} node,
which represents an unexplored branch (an \coqIn{Atom}). When the atom is a
\coqIn{call}, we use the backchaining procedure from
\cref{sec:preliminaries} to compute the two layers to attach to the tree:
alternatives form the Or-layer, and the premises of each applicable rule form
the corresponding And-layer. This expansion step is performed by the
\coqIn{step} procedure described in \cref{sec:step}.

The Rocq data type for And-Or trees is given in \cref{fig:tree-ty}. In
addition to \coqIn{Todo}, it provides two distinguished nodes, \koC and
\okC, which represent failed and completed branches (intuitively, an empty
disjunction and an empty conjunction, respectively).

The \orC node, written \(A \lor B_\sigma\), represents the addition of an
alternative \(B_\sigma\) to an existing disjunction $A$. The left subtree
\(A\) is optional and is absent once that branch has been fully explored.
The right alternative is paired with a substitution \(\sigma\), which becomes
the current substitution when backtracking to \(B\).\marginpar{why option and not KO?}

The \andC node, written \(A \land_{B_0} B\), represents the addition of a
subquery \(B\) to be solved after \(A\). We call \(B_0\) the \emph{reset
point} for \(B\): it is used to restore the initial state of \(B\) when
backtracking occurs within \(A\). An example is shown in \cref{sec:na}.

A graphical representation of a tree is shown in \cref{tree-ex1}. For
compactness, we depict \andC and \orC nodes as $n$-ary (rather than binary),
with children associating to the right. The \koC node acts as the terminating
element of an \orC list, while \okC is the terminating element of an \andC
list.

\subsection{The \step procedure}\label{sec:step}

The \step procedure takes as input a program, a set of variables, a
substitution, and a tree, and returns an updated set of variables, a
\steptag, and an updated tree.  

The set of variables \emph{v} given in input to step are used and updated when
a backchaining operation takes place. A call to \step produces a good result if
\emph{v} contains all the variables in the tree. This guarantees that any call
to \emph{bc} returns a list of atoms whose variables are disjoint from
the variables of the current working tree.\marginpar{not true in figure:fix + also fix in \cref{sec:cut-op}}

The \steptag (see~\cref{type:steptag}) indicates the kind of an internal tree step:
\cI{CutBrothers} denotes the interpretation of a superficial cut, i.e., a cut
whose parent nodes are all \andC-nodes. \cI{Expanded} denotes the interpretation
of non-superficial cuts or predicate calls. \cI{Failure} and \cI{Success} are
returned for, respectively, \failed and \success trees.


The step procedure is intended to evaluate atoms,
that is, it leaves unchanged the tree iff its \pathend is not an atom, i.e.
if it is a success- or a failed-tree.

\mvspace{}

\deflemma[lemma:failed]{tex_code/failed_step.tex}
\mvspace{}

\textit{The interpretation of a call} to a term $c$ stars by calling the
\backchain function on $c$. The result of the backchain is a list $l$.
If $l$ is empty then the current call is replaced by the \koC node,
otherwise it is replaced by a right-skewed tree made by \orC inner-nodes
and each leave correspod to a list of atom $e$ in $l$.
If $e$ is empty then it is mapped to the \okC tree, otherwise it is mapped
to a right-skewed tree made by \andC inner-nodes. 

In \cref{tree-ex1}, we provide a clear example of a call to \step on the query\marginpar{sottolineare le sostituzioni}
\eI{q 0 R} on the program $P$ in \cref{fig:prog}. Let $c_0$, $c_1$ and $c_2$ be
the childreen of the root. $c_0$, by construction is the \mnone tree, while
$c_1$ and $c_2$ correspod respectively to the premises of rules $r_1$ and $r_2$
in $P$. We need the first \mnone subtree so that we can attach a
substituion to $c_1$. In particular, we note that the $c_1$ (resp. $c_2$) are
related to the substitution $\sigma_1$ (resp. $\sigma_2$). The value of
$\sigma_1$ and $\sigma_2$ are the same as in \cref{sec:cut-op}. The reset points
in the tree are marked with the $R$ symbol. $R_1 \coloneq [\eI{f Y Z, !}]$, $R_2
\coloneq [\eI{!}]$ and $R_3 \coloneq \eI{f Y Z}$, they are essentially the list
of atoms that allowed to generate the current subtree. Other example of call to
the \step procedure triggering a backchain are \cref{tree-ex2,tree-ex3,tree-ex5}.

\textit{The interpretation of a cut}
has three main impacts: at first the cut is replaced by the \okC node, then
some special subtrees, in the scope of the \cutC, are cut away: in particular
we need to soft-kill the left-siblings of the \cutC and hard-kill the right-uncles
of the the \cutC.

\begin{definition}[Left-siblings (resp. right-sibling) and Right-uncles]
  Given a node $A$, the left-siblings (resp. right-sibling) of $A$
  are the list of subtrees sharing the same parent of $A$ and that appear
  on its left (resp. right). The right-uncles of $A$ are the list 
  of right-sibling of the father of $A$.
\end{definition}

\begin{definition}[Hard-kill, \cutr and Soft-kill, \cutl]
  Given a tree $t$, hard-kill replaces the given subtree with the \koC node.
  If $t$ is a success-tree, then soft-kill replaces with \koC all subtrees
  that are not part of the path in $t$ leading to the \okC node.
\end{definition}

\cref{lemma:failed}, \step does not make any progression on the tree being
interpreted. To solve this problem, we need a routine capable of backtracking in
case of failures. This routine return the backtracked tree if it exists,
\mnone otherwise.

In \cref{tree-ex3}, we are facing a failure: the interpreter has evaluated the

of \na, in this example, is to kill the path leading to this failure, while
reseting the failure to its original shape. We see how the reset point plays a
major role in this case. At first we are killing the \okC node under the
subsitution $\sigma_3$, since this tree have been entirely explored and led to
no solution, then we replace the \koC node with the information stored in $R_1$.

able to evaluate this node under the subsitutution $\sigma_4$. More concretely,
we have uncessefully tried rule \eI{r 0 0}, therefore, we need to continue by
trying rule \eI{r 0 1}.

remain with a tree having all failing path. The \na procedure keeps removing

\subsection{The \run inductive}\label{sec:runT}

The inductive \run is modeled as a function taking $4$ inputs and returning
$3$ outputs. The inputs are the
program, a set of variables $v$, an initial substitution $\sigma$, and a tree
$t$. The outputs are an optional object $r$ containing a substitution $\sigma'$
and an optional tree $t'$, and a boolean $b$ and a set of updated variables $v_1$.
The very interesting piece of information is the result $r$, if $None$,
it tells that the interpretation failed, otherwise, $\sigma'$
represents the most-general unificator
that makes the execution of the tree $t$ under the initial
substitution $\sigma$ succeeds: $\sigma'$ is an extension of $\sigma$.
The tree $t'$ is the updated tree containing the alternatives that have
not yet been explored, if these alternatives do not exists, $t'$ is $None$.
The output $b$ and $v_1$ are there to tell respectively if during the
execution a superficial cut has been evaluated, and what is the updated
set of variables after the interpretation.

The procedure \run is based on four main derivation rules, shown in\marginpar{dire is\_cb cos'è}
\cref{fig:run-rules}. (\textsc{StopT}) If the \pathend of the tree $t$ is a success, 
the substitution $\sigma'$ is retrived in $t$ from $\sigma$ and the input tree 
is cleaned of its successful
path. (\textsc{StepT}) If the \pathend of $t$ is an atom, then \step is
invoked to evaluate $t$, and \run is recursively called on the new
tree. (\textsc{BackT}) If the \pathend of $t$ is a failure,
\na is called to clear the failed path; if the resulting cleaned tree $t'$ 
exists, \run is recursively called on it. Finally, (\textsc{FailT}) takes into
account tree with no solutions.

\subsection{Valid trees (\vast)}

The inductive tree allows one to generate a large number of
trees, some of which are not valid, in the sense that they cannot be produced
starting from a given query. The class of valid trees is characterized by the
function shown in \cref{fig:vt}.


While all base cases of tree are considered valid, we need to analyze 
carefully the cases for the \orC and \andC constructors.

For the \orC constructor, we distinguish two cases depending on whether the
lhs exists. If it does not exist, then the ths
must be a valid tree. Otherwise, the lhs must itself be a valid tree,
and the rhs is either the \koC tree, since it may have been removed by the
evaluation of a superficial cut in the lhs, or it has not yet been explored.
In the latter case, it is a \cI{base_or} tree, namely the right-skewed tree
formed by a disjunction of conjunctions that is genereated after a
succeful backchain to a call.

For the \andC constructor, the lhs is required to be a valid tree. The shape
of the rhs depends on whether the lhs is a success. If the lhs is not
successful, then the rhs has never been explored: the procedures \step and
\na modify the rhs only when the lhs succeeds. In this case, the lhs must be
the right-skewed tree containing conjunctions of premises atoms,

\subsection{From trees to lists (\ttl)}

The translation of a tree to a en \elpiP state is done thanks to the
\ttl function. In \cref{fig:ttl} we give junst the implementation of the
base cases, the full implementation is available at \href{https://github.com/FissoreD/elpi-formalization/blob/ho-check-ffun/theories/t2l.v}{\emph{this}} link.

The function \ttl takes the tree $t_0$ we want to translate, a subsitution
$\sigma_0$ and a list of choice points $cp$. These choice points represent
alternatives that appears at the same level of the current node, such as, for
example, the right-siblings of a \orC node. The \okC node represent one succeful
alternative, thereofre it is translated into a singleton list with the empty
list of goals. The \koC node represent a failure, i.e. it is mapped to the
empty list of alternatives. Finally, atoms are mapped to one alternative
containing a single goal with the empty cut-alternative list. They cannot point
to $cp$ since they are not right-uncle subtrees.

We have omitted the code for the translation of the \orC and \andC constructor
since it is quite complex, but, we give the intuition behind this translation by
means of examples.

The translation of $A \lor B_\sigma$ creates two list of alternatives,
one for the $A$ and the other for $B$. The alternatives of the rhs are valid
choice points for the lhs and should be passed to the translation of $A$.
The two list of alternatives can be concatenated and, each atom, should add
$cp$ as new cut-to alternatives: $A$ and $B$ are one level lower wrt $cp$ and
therefore the cut they have should point to $cp$.

The translation of $A \land_{B_0} B$ implies the translation of $A$. If the
translation of $A$ returns an empty list we return the empty list of
alternatives without even touching $B$ nor $B_0$. Otherwise the translation
returns a list $(\sigma_0, g) :: a$. By the semantics of \run the $B$ node
represent the continuation of the first alternatives in $A$, i.e. $g$, whereas
$B_0$\marginpar{dirlo meglio all'inizio} is the continuation of goals for each
alternative in $a$. While performing these translation, we need to carefully
update the cut-atlernatives.
